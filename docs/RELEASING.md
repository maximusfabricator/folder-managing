# Как выпустить новую версию

Начиная с 2.2.0 приложение само узнаёт о новых версиях: раз в день оно скачивает с последнего релиза на GitHub
маленький файл `update.json` и его подпись `update.json.sig`. Поэтому каждый релиз должен содержать три файла:
установщик, `update.json` и `update.json.sig`. Всё это делает один скрипт — `scripts\release\Publish-Release.ps1`.

## Что нужно один раз

- Git, GitHub CLI (`gh`) с входом в аккаунт: `gh auth login`.
- .NET 10 SDK и Windows SDK (как для `Build-UserRelease.ps1`).
- Сертификат релизов в `artifacts\certs`: `FolderManaging-Release.pfx` и `FolderManaging-Release.password.txt`.
- Хук `.git\hooks\commit-msg` (убирает лишнюю строку соавтора из сообщений коммитов). Скрипт проверяет, что он на месте.

## Что обязательно хранить в резервной копии

**`artifacts\certs\FolderManaging-Release.pfx` и `artifacts\certs\FolderManaging-Release.password.txt`.**

Этим ключом подписываются и пакет приложения, и `update.json`. Открытая часть ключа встроена в приложение
(`src\FolderManaging.Core\Updates\UpdateSignature.cs`). Если ключ потерять, установленные копии больше не примут
ни одного обновления: людям придётся один раз скачать и установить новую версию вручную. Храните обе вещи вне
компьютера (зашифрованная флешка, менеджер паролей), никогда не коммитьте их и никому не отправляйте.

Смена ключа в будущем: добавьте новый открытый ключ в список `TrustedKeys` рядом со старым, выпустите версию,
подписанную старым ключом, и только через некоторое время переходите на новый ключ.

## Выпуск версии шаг за шагом

1. Поднимите версию в двух местах (пример для 2.3.0):
   - `Directory.Build.props`: `<Version>2.3.0</Version>`;
   - `sparse\AppxManifest.User.xml`: `Version="2.3.0.0"`.
2. Добавьте раздел в самый верх `CHANGELOG.md`, в том же простом стиле, что и раньше:

   ```
   ## 2.3.0 — 2026-11-15

   ### New

   - ...
   ```

   Между версией и датой — длинное тире «—». Текст этого раздела увидят пользователи в окне обновления
   (без разметки) и на странице релиза.
3. Закоммитьте изменения и проверьте, что вы на ветке `main`:

   ```
   git commit -am "Folder Managing 2.3.0"
   ```

   (`-a` берёт только уже отслеживаемые файлы; новые файлы добавьте отдельно через `git add <файл>`.
   Не используйте `git add -A`: он добавил бы и личный `docs\Samtalehistorikk-laerer-nb.md`.)
4. Пробный прогон — собирает, создаёт и подписывает `update.json`, но ничего не публикует:

   ```
   powershell -ExecutionPolicy Bypass -File scripts\release\Publish-Release.ps1 -DryRun
   ```

   Результат лежит в `artifacts\release` (установщик) и `artifacts\release\publish` (`update.json`,
   `update.json.sig`, `release-notes.md`). Можно открыть `release-notes.md` и посмотреть текст релиза.
5. Настоящий выпуск:

   ```
   powershell -ExecutionPolicy Bypass -File scripts\release\Publish-Release.ps1
   ```

   Скрипт снова всё проверит, соберёт установщик, создаст тег `v2.3.0` с сообщением «Folder Managing 2.3.0»,
   отправит `main` и тег на GitHub, создаст релиз (сначала черновик, потом опубликует его как последний) и в конце
   скачает `update.json` с GitHub без входа в аккаунт и проверит версию и подпись. Сборка занимает несколько минут.
   В конце скрипт печатает ссылку на релиз и SHA-256 установщика.
6. Проверка с компьютера с установленной программой (необязательно):

   ```
   foldermanaging-cli update --check
   ```

   Должно быть «up to date» на новой версии или «a newer version is available» на старой.

## Что проверяет скрипт перед выпуском

- вы на `main`, нет незакоммиченных изменений (неотслеживаемый `docs\Samtalehistorikk-laerer-nb.md` не мешает),
  `main` не отстаёт от GitHub;
- версия одинаковая в `Directory.Build.props`, `AppxManifest.User.xml` и в верхнем разделе `CHANGELOG.md`;
- последний коммит сделан вашим именем и без строки `Co-authored-by`;
- хук `commit-msg` установлен;
- такого тега и релиза ещё нет, и новая версия больше последней опубликованной;
- ключ сертификата совпадает с ключом, встроенным в приложение (иначе приложение отвергло бы обновление).

## Если что-то пошло не так

- **Скрипт остановился на проверках.** Он ничего не изменил. Исправьте то, о чём он пишет, и запустите снова.
- **Ошибка сборки.** Тег и релиз ещё не созданы. Исправьте ошибку, закоммитьте, запустите снова.
- **Сбой после создания тега или во время загрузки на GitHub.** Просто запустите скрипт ещё раз. Тег на том же коммите
  он использует повторно, недоделанный черновик релиза удалит и создаст заново. Опубликованный релиз он только
  проверит. Двойных тегов и релизов не будет.
- **Нашлась ошибка в коде после создания тега, но до публикации.** Удалите черновик релиза на GitHub (если он есть) и
  тег (`git tag -d v2.3.0`, а если он уже на GitHub — `git push origin :refs/tags/v2.3.0`), исправьте, закоммитьте,
  запустите снова. Если релиз уже опубликован, не трогайте его — выпустите следующую версию (2.3.1).
- **Проверка в конце пишет, что latest ещё старый.** GitHub иногда обновляет ссылку `latest` с задержкой. Запустите
  скрипт ещё раз через минуту: он увидит опубликованный релиз и только повторит проверку.
- **Не тот текст в релизе.** Текст на странице релиза можно поправить на GitHub. Текст в окне обновления берётся из
  `update.json`; его можно заменить, только перевыпустив `update.json` и `update.json.sig` вместе (проще выпустить
  следующую версию).
- **Сертификат или пароль не найдены.** Восстановите `artifacts\certs` из резервной копии. Не создавайте новый
  сертификат: приложения у пользователей примут только старый ключ.

## Как это выглядит у пользователя

Примерно через полторы минуты после запуска значка в трее, а затем раз в день, приложение скачивает `update.json`
и проверяет подпись. Если есть новая версия, открывается небольшое окно со списком изменений и кнопками
«Обновить», «Позже» и «Пропустить эту версию». Окно не перехватывает фокус и ждёт, пока человек в полноэкранной игре
или презентации. «Обновить» скачивает установщик из того же релиза, сверяет размер и SHA-256 с подписанным
`update.json`, закрывает приложение и устанавливает новую версию без страниц мастера; потом приложение запускается
снова. Настройки, автозапуск и ярлык на рабочем столе сохраняются. Проверку можно отключить в параметрах.
Версии 2.1.1 и старше обновляться сами не умеют — там нужно один раз установить 2.2.0 вручную.
