# Folder Managing — документация по реализованным частям (Companion, state.json, оболочка, логи)

Документ описывает текущее состояние кода в репозитории: что сделано, куда пишутся логи, как интерпретировать сообщения, почему что-то может не работать, и что **ещё не** реализовано.

---

## 1. Обзор архитектуры

| Компонент | Назначение |
|-----------|------------|
| **FolderManaging.Core** | Модели (`AppStateDocument`, папки, теги, пресеты цветов меню), пути (`AppPaths`), JSON-хранилище (`JsonFolderStateStore`), применение значков папок (`FolderIconManager`), чтение меню из состояния (`MenuStateReader`, `MenuPresetNormalizer`), лог `TraceLog`. |
| **FolderManaging.Shell** | COM-расширение проводника: построение контекстного меню (`MenuBuilder`), выполнение команд (`MenuActionExplorerCommand`, `ComVerbExecutor`), расширенное логирование (`ExtremeLogger`), дублирование ключевых строк в `shell-menu.log` через `ShellActionLog`. |
| **FolderManaging.Cli** | Консольные команды (в т.ч. контекстное меню по классической регистрации), действия `--action`, установка/снятие меню, **`force-refresh-icons`**, диагностика через `TraceLog`. |
| **FolderManaging.Companion** | WPF-приложение на **WPF-UI (lepoco)**, пакет NuGet **`WPF-UI` 4.2.1**, главное окно **`FluentWindow`** с **Mica**, **`NavigationView`**, страницы настроек цветов и меток, запись в `state.json`. |

Важно: NuGet-пакет называется именно **`WPF-UI`** (с дефисом). Пакет **`WPF.UI`** / ошибочный `Wpf.Ui` с другим издателем — это **другая** библиотека и не подходит под задачу «нативный Fluent как у lepoco».

## 2. Файл состояния `state.json`

### 2.1 Расположение

- Каталог данных: **`%USERPROFILE%\.FolderManaging\`** (классическая установка; для MSIX возможна виртуализация путей — см. комментарии в `AppPaths.cs`).
- Файл: **`%USERPROFILE%\.FolderManaging\state.json`**.

### 2.2 Основные поля (camelCase в JSON)

| Поле | Тип | Описание |
|------|-----|----------|
| `version` | number | Версия схемы документа. |
| `folders` | array | Записи по папкам: путь, теги, закрепление, токен цвета и т.д. |
| `menuColors` | array | Пресеты цветов для **контекстного меню**: стабильный `id` (например `coral`, `ocean`, `mint`, `plum`), подпись `label`, цвет **`hexRgb`** — строка из **6** шестнадцатеричных цифр **без `#`** (например `FF7256`). |
| `menuTags` | array | Пресеты меток: `id`, `label` для пунктов «Tag — …» в меню. |

### 2.3 Нормализация при загрузке

Класс **`MenuPresetNormalizer.Merge`** вызывается после чтения JSON (в т.ч. в **`JsonFolderStateStore.LoadAsync`** и **`LoadSynchronously`**):

- Для каждого встроенного цвета из **`FolderColors.PresetRgb`** гарантируется строка в **`menuColors`** с корректным `hexRgb`, если в файле не было или HEX невалиден.
- Если **`menuTags`** пуст, подставляются метки по умолчанию (work, personal, later, archive и т.п., как в коде нормализатора).

Companion при сохранении снова вызывает **`Merge`** перед записью (`SaveSynchronously`), чтобы файл оставался согласованным.

## 3. Companion (настройки «как в Windows 11»)

### 3.1 Технологии

- **WPF** + **WPF-UI 4.2.1** (`WPF-UI` в `.csproj`).
- Пространство имён XAML: **`http://schemas.lepo.co/wpfui/2022/xaml`** (префикс обычно `ui:`).
- Главное окно: **`ui:FluentWindow`** — `WindowBackdropType="Mica"`, `ExtendsContentIntoTitleBar="True"`.
- Тема: в **`App.OnStartup`** вызывается **`ApplicationThemeManager.Apply`**: системная светлая/тёмная тема и отдельно ветка для **высокого контраста**; на окне после загрузки — **`SystemThemeWatcher.Watch(..., Mica, ...)`**.
- В **`App.xaml`** подключены **`ThemesDictionary`** и **`ControlsDictionary`**.

### 3.2 Навигация и страницы

- **`NavigationView`**: пункты **«Цвета папок»** (`ColorsPage`) и **«Метки»** (`TagsPage`) с **`TargetPageType`**.
- В **нижнем меню** (`FooterMenuItems`): **«Сброс значка папки…»** — выбор папки через **WinForms `FolderBrowserDialog`**, вызов **`FolderIconManager.RemoveCustomization`**.

### 3.3 Страница цветов

- Список карточек (**`ui:CardControl`**) по одной на каждый **`MenuColorPreset`** из `state.json`.
- Иконка-образец: конвертер **`HexRgbToBrushConverter`** (RGB из строки в `SolidColorBrush`).
- Поле имени: **`ui:TextBox`** с **`PlaceholderText`**; при изменении текста вызывается **`CompanionState.Save()`** (немедленная запись `state.json`).
- Кнопка **«Цвет…»**: раскрывает встроенный редактор (ползунки R/G/B и поле HEX); изменения снова сохраняются в JSON и обновляют превью списка.

**Замечание:** вместо встроенного элемента **`ui:ColorPicker`** (спектр) сейчас используется связка **RGB + HEX** — проще поддерживать и она не зависит от точного API событий `ColorPicker` в вашей версии библиотеки. При желании спектр можно заменить на `ColorPicker` отдельной итерацией.

### 3.4 Страница меток

- Карточки с **`id`** (только отображение) и редактируемым **`label`**.
- Добавление: поле ввода + кнопка **«Добавить»**; **`id`** генерируется из названия (slug), при коллизии добавляется суффикс `-1`, `-2`, …
- Удаление: кнопка с **`SymbolIcon Delete24`**.

### 3.5 Общее состояние в памяти

**`CompanionState`** держит один экземпляр **`AppStateDocument`**, загруженный через **`JsonFolderStateStore.LoadSynchronously`** при первом обращении. Сохранение — **`JsonFolderStateStore.SaveSynchronously`**.

## 4. Оболочка (Shell) и меню

### 4.1 Откуда берутся подписи пунктов меню

**`MenuBuilder`** читает объединённый документ через **`MenuStateReader.GetMerged()`** (кэш по **времени изменения файла** `state.json`):

- Цвета: порядок как у ключей **`FolderColors.PresetRgb`**, подписи и токены из **`menuColors`**.
- Метки: список **`menuTags`** в порядке JSON.

Удалён отдельный статический список **`ShellMenuDefaults`** — меню завязано на конфиг.

### 4.2 Применение цвета папки

**`FolderIconManager.Apply(folder, colorId)`**:

1. **`MenuStateReader.TryGetMenuTint(colorId, out tint)`** — сначала цвет из **`menuColors`**, иначе встроенный **`FolderColors`**.
2. Если оттенок **не совпадает** с встроенным пресетом для этого `id`, вызывается **`ApplyRgb`** (генерация `rgb-….ico` в каталоге сгенерированных иконок).
3. Иначе — прежняя ветка с готовым **`{id}.ico`** и **`EnsurePresetIcons`**.

Таким образом, смена HEX в Companion влияет на реальный цвет значка без смены стабильного **`id`** в меню и в `ColorToken`.

## 5. Логирование: куда смотреть и что означают строки

### 5.1 `shell-menu.log` (TraceLog + Shell)

**`TraceLog.Append("shell-menu.log", …)`** дублирует каждую строку в **несколько корней** (см. `TraceLog.LogRoots()`):

1. **`%LocalAppData%\FolderManaging\shell-menu.log`**
2. **`%USERPROFILE%\.FolderManaging\shell-menu.log`**
3. Каталог из **`%PUBLIC%`** (часто **`C:\Users\Public`**) — файл **`shell-menu.log`** там же по имени.

При первой записи может появиться подсказка **`%USERPROFILE%\.FolderManaging\WHERE-ARE-LOGS.txt`** с путями к двум основным копиям лога.

**Типичные префиксы из Core (`FolderIconManager.Apply`):**

| Строка (фрагмент) | Смысл |
|-------------------|--------|
| `[CORE] [STEP 0] Apply enter …` | Вход в применение цвета. |
| `[CORE] [STEP 1] resolved fullFolder=…` | Путь папки нормализован. |
| `[CORE] [STEP 2] write-probe` | Проверка возможности записи в папку (временный файл). |
| `[CORE] [FAIL STEP 2] write-probe failed` | **Нет прав на запись** в каталог (защищённые расположения, политика, только чтение). |
| `[CORE] [STEP 2b] custom tint … -> ApplyRgb` | Выбран нестандартный RGB из `state.json`, пойдёт ветка **RGB-иконки**. |
| `[CORE] [STEP 3] EnsurePresetIcons` | Проверка/генерация пресетных `.ico`. |
| `[CORE] [STEP 4] iconFullPath=…` | Путь к `.ico` для классической ветки. |
| `[CORE] [STEP 8 WRITE] …` | Запись `desktop.ini` (UTF-16 LE с BOM в коде). |
| `[CORE] [STEP 11] nudged Explorer` | Уведомление оболочки об обновлении значка. |

**Из CLI (`Program.cs`):** строки вида **`[CLI] [START]`**, **`[PROCESS]`**, **`[SUCCESS]`**, **`[FAIL]`** для действий color / reset / tag / pin / unpin.

**Из COM (`MenuActionExplorerCommand`):** дублирование в тот же файл через **`ShellActionLog.Write`**, например:

- `[COM] [START] Invoke verb=…`
- `[COM] [PROCESS] resolved path=…`
- `[COM] [FAIL] path unresolved … hr=…` — **путь к папке из выделения не получен** (типично для нестандартного контекста или ошибки `IShellItemArray`).
- `[COM] [SUCCESS] …` / `[COM] [FAIL] verb-execution …` — успех или исключение при выполнении команды.

### 5.2 `FolderManager_ExtremeTrace.log` (ExtremeLogger)

Пишется из **только Shell** (COM). Назначение — «записать хоть куда-нибудь» при сбоях в dllhost/MSIX: несколько целевых путей (профиль, LocalAppData, Temp, ProgramData, Public — см. реализацию **`ExtremeLogger`**).

Полезно при:

- падениях до обычного лога;
- сомнениях в **разрядности** (x64), путях сборки, **`USERPROFILE`** в изолированном процессе.

В начале **`Invoke`** часто вызывается **`LogEnvironmentSnapshot`**: PID, identity, каталоги, переменные среды — чтобы понять **в каком пользователе и из какой папки** грузится DLL.

## 6. Команда сброса кэша значков Explorer

Реализовано в **CLI** и дублируется **скриптом PowerShell**.

| Механизм | Как вызвать |
|----------|-------------|
| CLI | `FolderManaging.Cli force-refresh-icons` (первый аргумент). |
| Скрипт | `scripts\Force-Refresh-ExplorerIcons.ps1` |

Действия: завершение **explorer.exe**, удаление **`%LocalAppData%\IconCache.db`**, маски **`%LocalAppData%\Microsoft\Windows\Explorer\iconcache*`**, запуск **explorer.exe** снова.

**Важно:** на время закрываются все окна проводника; часть файлов кэша может не удалиться, если процесс ещё держит дескриптор — тогда повторить после паузы или перезагрузки.

## 7. Почему приложение или функции «могут не работать»

### 7.1 Companion (WPF)

| Симптом | Возможная причина |
|---------|-------------------|
| Не собирается / не копируется `.exe` | Запущен **`FolderManaging.Companion.exe`** — закройте процесс и пересоберите. |
| Пустое/битое окно, ошибки XAML | Неверный xmlns (нужен **`…/wpfui/2022/xaml`**). Неверный пакет (нужен **`WPF-UI`**, не `WPF.UI`). |
| Mica не виден | Старый Windows 10 без нужных API, отключены эффекты, RDP без композиции, политики — возможен откат к обычному фону. |
| «Тёмная» тема в `App.xaml` не совпадает с системой | В ресурсах задан **`ThemesDictionary Theme="Dark"`** как база; фактическая тема подстраивается **`ApplicationThemeManager.Apply`** + watcher — при полном несоответствии ожиданий можно синхронизировать атрибут `Theme` в XAML отдельной доработкой. |
| Конфликт типов в коде | В проекте включены **и WPF, и WinForms** — для типов вроде `UserControl`, `Application`, `MessageBox` нужны **полные имена** (`System.Windows.Controls.UserControl` и т.д.), как в текущем коде. |

### 7.2 Контекстное меню / Shell

| Симптом | Возможная причина |
|---------|-------------------|
| Пункты не обновились после правки `state.json` | **`MenuStateReader`** кэширует по **mtime** файла — сохраните файл с диска (Companion так и делает). Кратковременный кэш в других местах (например pinned) может задержать обновление до ~750 ms. |
| Цвет не тот | Проверьте **`hexRgb`** (6 символов). Смотрите **`shell-menu.log`**: ветка **`[STEP 2b] … ApplyRgb`** vs пресетная. |
| Нет прав на папку | Строка **`[FAIL STEP 2] write-probe`** — перенос папки, запуск от администратора обычно не помогает для «пользовательских» папок; нужна запись в сам каталог. |
| COM не вызывается | Не зарегистрирована оболочка / не тот пакет MSIX / не та разрядность — это уже развёртывание, не логика Companion. |

### 7.3 MSIX и пути

Для упакованного приложения пути к **`state.json`** и логам могут **виртуализироваться** под профиль пакета (`LocalCache` и т.д.). Тогда проводник и Companion должны быть согласованы **одной** установкой одного и того же пакета/пользователя. Подробности — в комментариях **`AppPaths`**.

## 8. Что уже реализовано

- **Хранилище JSON** с папками и **`menuColors` / `menuTags`**, нормализация при загрузке и при сохранении из Companion.
- **Companion**: Fluent **Mica**, навигация, страницы цветов и меток, страница **Manage Folders** (таблица папок с цветом/метками/закреплением и быстрыми действиями), немедленное сохранение в **`state.json`**, сброс значка папки через диалог выбора каталога.
- **Shell**: меню цветов/меток из **`state.json`**; применение цвета с учётом кастомного RGB; логи COM + зеркало в **`shell-menu.log`**.
- **Core**: **`MenuStateReader`**, **`MenuPresetNormalizer`**, **`FolderStateTagSync`** (очистка тега у всех папок при удалении пресета), **`JsonFolderStateStore.LoadSynchronously` / `SaveSynchronously`**, ветка **`Apply` / `ApplyRgb`**, **`FolderIconManager.RequestExplorerRefreshForFolder`** (доп. уведомление Explorer после правок только в JSON).
- **CLI**: команда **`force-refresh-icons`** и скрипт **`scripts/Force-Refresh-ExplorerIcons.ps1`**.
- **Диагностика**: **`TraceLog`**, **`ExtremeLogger`**, **`ShellActionLog`**, подсказка **`WHERE-ARE-LOGS.txt`**.

## 9. Что реализовано частично или не сделано

| Область | Статус |
|---------|--------|
| **Спектральный `ColorPicker` из WPF-UI** | Не подключён как отдельный контрол; вместо него **RGB + HEX** на странице цветов. |
| **Полная копия «Параметров Windows»** | Сделан **Fluent-скелет** (карточки, навигация, Mica), но не все типы контролов WinUI (например `SettingsExpander` 1:1) и не весь набор страниц настроек. |
| **Синхронизация `ThemesDictionary Theme=` в XAML с ОС** | Базовая тема в merged dictionary задана статически; приложение **переключает тему в коде** — при желании можно выровнять без «мигания» при старте. |
| **Редактирование стабильного `id` цвета** | Предполагаются фиксированные **`coral`/`ocean`/…** для совместимости с существующими командами; в UI **id** только показывается, не редактируется. |
| **Фильтры по тегам / поиск по путям в Manage Folders** | Таблица показывает все «кастомизированные» папки; **нет** отдельного поиска/фильтра по тексту. |
| **Полная документация MSIX/регистрации COM** | В этом файле не дублируется; зависит от ваших скриптов sparse MSIX и манифеста. |

## 10. Как проверить цепочку «Companion → меню → значок»

1. Запустите **Companion**, измените подпись или цвет, убедитесь что **`%USERPROFILE%\.FolderManaging\state.json`** обновился (время изменения файла).
2. Откройте **`shell-menu.log`** в профиле или LocalAppData и выполните действие из меню — должны появиться строки **`[COM]`** или при вызове CLI — **`[CLI]`**.
3. Если значок визуально старый — один раз выполните **`force-refresh-icons`** или скрипт из раздела 6.
